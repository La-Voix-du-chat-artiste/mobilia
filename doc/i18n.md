# Internationalisation

Mobilia speaks French (`:fr`, the language it was written in and the default),
English (`:en`) and Simplified Chinese (`:zh`).

## Picking a language

`?locale=xx` wins, then the language chosen earlier in the session, then the
default. `ApplicationController#use_selected_locale` resolves it around each
action (so it cannot leak into the next request on the same thread), the switcher
in `app/views/application/_locale_switcher.html.slim` sets it, and an unknown
value falls back to `:fr` instead of raising. Background jobs and mailers carry
the locale they were enqueued in (`ApplicationMailer`), so a planning email is
written in the language the person who sent it was reading.

## Where translations live

One file per feature area, per locale:

| file | holds |
| --- | --- |
| `config/locales/common.{fr,en,zh}.yml` | vocabulary shared by several screens (`common.*`) and controller flash messages (`flash.*`) |
| `config/locales/views_<area>.{fr,en,zh}.yml` | every string of one area's templates (`views.*`) |
| `config/locales/activerecord.*` | model, attribute and enum labels (used by `human_enum_name`, `model_name.human`) |
| `config/locales/simple_form.*` | form labels, placeholders, hints |
| `config/locales/seo.*` | page titles and meta descriptions |
| `config/locales/mailers.*`, `action_policy.*` | mailer subjects, "not allowed" message |
| `config/locales/zh.framework.yml` | dates, times, numbers and validation messages for `:zh`, generated from rails-i18n (see below) |

There are **no locale fallbacks**. Every key must exist in all three locales, so
a missing translation is a failing spec rather than a page of half-English
Chinese. Rails i18n ships French and English framework strings; Simplified
Chinese ships as `zh-CN`, which is why `:zh` gets its own generated file:

```
bin/rails i18n:zh_framework
```

## Key naming

A key describes **where** the string is, not what it says:

* `app/views/customers/index.html.slim` → `views.customers.index.*`
* `app/views/customers/_form.html.slim` → `views.customers.form.*`
* `app/views/daily_quests/missions/new.html.slim` → `views.daily_quests.missions.new.*`
* `app/views/application/_header.html.slim` → `views.application.header.*`

The leading underscore of a partial is dropped, nested directories become
nested keys, and the leaf is short and about the role of the text: `title`,
`submit`, `empty`, `confirm_delete`, `column.transporter`. Controller messages
are `flash.<controller>.<key>` (`flash.customers.created`).

Always write the full key (`t('views.customers.index.title')`), never the
relative `t('.title')`: full keys can be grepped, and the i18n lint spec
compares them with the keys defined in the locale files.

Before inventing a key, check `common.*` — `delete`, `edit`, `back`, `search`,
`select`, `export_pdf`, `previous_business_day` and friends already exist.

## Writing a value

* Keep `%{placeholders}` exactly as they are (`%{name}`, `%{count}`, `%{date}`).
* A value that contains HTML is named with an `_html` suffix and rendered with
  `== t('...')`; every other value is rendered with `= t('...')`, which escapes
  it, and must therefore contain no markup. Inside a `simple_form` `hint:`, `t`
  does not mark the value safe and simple_form escapes plain strings, so those
  call sites add `.html_safe` (see
  `views.sessions.new.demo_password_hint_html`).
* French is the source of truth: extracting a string into `views_*.fr.yml` must
  not change a single character of the French UI.
* Chinese has one plural form: give `one` and `other` the same text rather than
  relying on English pluralisation.
* Do not translate product and proper names (`Mobilia`, `La Voix du Chat
  Artiste`, `GitHub`), technical acronyms (`PDF`, `OSRM`, `BAN`), e-mail
  addresses, phone numbers, postcodes or tool names (`Leaflet`).

## Adding a language

1. Add it to `config.i18n.available_locales` in `config/application.rb`.
2. Add the framework strings (dates, times, numbers, validation messages). If
   rails-i18n only ships a regional variant (`zh-CN`), extend
   `lib/tasks/i18n.rake`.
3. Copy every `*.fr.yml` into `*.<locale>.yml` and translate the values.
4. Add the label to `ApplicationHelper::LOCALE_LABELS`.

## Checks

```
bundle exec rspec spec/i18n    # parity between locales + every page in every language
bundle exec rspec              # the whole suite, which runs with :fr
```

## Checklist for translating one area

Work one area (one directory of templates) at a time; the area owns three files:
`config/locales/views_<area>.fr.yml`, `.en.yml` and `.zh.yml`.

1. Read every template of the area and list its user-visible strings: text
   nodes, `link_to`/`button_to` labels, `submit` values, `placeholder`, `title`,
   `alt`, `aria-label`, `data-turbo-confirm` messages, `sr-only` text, empty
   states, table headers.
2. Replace each literal with `t('views.<controller>.<template>.<key>')`. Strings
   built by interpolation become `t('...', name: value)` with `%{name}` in the
   value. Casing and `capitalize`/`html_safe` handling move into the value.
3. Write the three locale files with identical key trees. French keeps the
   original wording byte for byte; English and Chinese are written, not
   transliterated — check the terminology already used in
   `config/locales/activerecord.zh.yml` and `config/locales/simple_form.zh.yml`.
4. Leave alone: Tailwind classes, `data-*` attributes, `id`, `href`, SVG paths,
   model data (`company.name`, `customer.full_name`), values produced by helpers
   (`l(...)`, `number_to_human`), product names and technical acronyms.
5. Validate before calling the area done — replace `<area>` and the glob:

```
# key parity between the three files
~/.rvm/wrappers/ruby-4.0.4/bundle exec ruby -ryaml -e '
def paths(node, prefix = [], acc = []); node.is_a?(Hash) ? node.each { |k, v| paths(v, prefix + [k], acc) } : acc << prefix.join("."); acc; end
%w[fr en zh].each { |l| puts "#{l}: #{paths(YAML.load_file("config/locales/views_<area>.#{l}.yml")[l]).size} keys" }
fr = paths(YAML.load_file("config/locales/views_<area>.fr.yml")["fr"])
%w[en zh].each { |l| o = paths(YAML.load_file("config/locales/views_<area>.#{l}.yml")[l]); puts "#{l} missing #{(fr - o).inspect} extra #{(o - fr).inspect}" }'

# every template still compiles, and its embedded Ruby is valid
~/.rvm/wrappers/ruby-4.0.4/bundle exec ruby -e 'require "slim"; Dir["app/views/<area>/**/*.slim"].each { |f| RubyVM::InstructionSequence.compile(Slim::Engine.new.call(File.read(f))); puts "ok #{f}" }'

# nothing user-visible is left as a literal
grep -rnE "(['\"])[A-ZÀ-Ý][^'\"]{3,}\1|^\s*(\||=)\s*[A-ZÀ-Ý]" app/views/<area>
```
